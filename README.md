# 串口丢包统计工具

面向 SSCOM 等串口助手导出日志的 Windows 桌面工具。拖入 `.txt`、`.csv` 或 `.dat` 日志后，工具会先建立可复核的“方向 → 完整帧 → 序号”证据链，再统计接收方向的协议层丢包。

## 功能

- 支持重复拖入 TXT/CSV/DAT 日志，无需重启窗口；内容超出窗口时可用滚轮或右侧页面滚动条查看。
- 可一次拖入或通过“选择多份对比”导入多份**同一协议**日志；以当前确认的帧格式、序号和循环参数逐份复算，集中比较完整帧、CRC、截断、丢包率及最差循环，并可导出对比 CSV。
- 自动识别 SSCOM 5.00a 原生收/发标签（即使该标签因编码无法正常显示），并只将 `RX` 用于帧和丢包统计；无方向标记的日志会明确标为“方向未知”。
- 支持自定义固定帧，也会用 **CRC16-Modbus** 验证 Modbus RTU 响应并按字节计数自动确定变长帧长。
- 支持“自定义长度字段帧”模板：可配置帧头、长度字段偏移、长度字段 1/2/4 字节、大小端和调整值，用于私有变长协议。
- 接收缓存可跨多条串口记录拼帧；尾部不完整帧、帧内超时、CRC 错误、帧头前噪声均会单独计数，绝不当作完整帧。
- 自动推测序号位置和字节序，但界面会标为“候选”，必须由使用者核对。
- 循环模式只有在至少两个宽范围循环共同证明相同的序号范围时才启用。少于理论帧数 50% 的循环会标为采集冗余；界面同时显示“全部循环”和“纳入循环”两种丢包率，避免筛选被隐藏。
- 导出的 CSV 含每轮观察范围、重复数、是否纳入以及**确切缺失序号**。
- 若日志含 TX/RX，额外显示按时间顺序的请求–响应配对、未响应 TX、孤立 RX 与平均响应时间。这是通信健康度信息，**不计入 RX 丢包率**。
- “解析证据”页会逐帧显示来源日志行、时间、完整 HEX、提取序号及相邻帧判定；可另存为 CSV。跨两次接收拼成的帧会显示首尾日志行。
- 每个参数名旁的 `?` 可查看用途、填写口径与典型例子，避免把“总帧长”“长度字段”“循环理论帧数”等概念混用。
- “时间定位”页会按可设窗口（默认 60 秒）汇总有效 RX 帧、缺失帧、丢包率、平均/最大帧间隔，并将超过全局中位帧间隔 3 倍的间隔标为异常长间隔；没有可用时间戳时会明确提示无法定位。
- 循环纳入阈值（默认 50%）和收发超时（默认 1500 ms）可调；所有协议参数均可保存/加载为 JSON 方案，保证同一类日志可复现。
- 自动循环证据不足时，可同时填入“手动循环起始序号”和“手动理论帧数”；报告会明确标记该范围由使用者设定，而非自动推断。
- 可导出复现报告 JSON：包含输入文件名、大小、SHA-256 指纹、完整参数、方向识别、帧解析事件、收发核对和统计结果。报告不复制原始日志内容。

## 判断规则

1. **方向**：SSCOM 原生标签或可读 TX/RX 标签优先。发现方向标签后，只有 RX 字节进入帧解析；没有方向标签时才允许分析全部 HEX，同时显示警告。
2. **完整帧**：固定帧需满足帧头和帧长；Modbus RTU 需满足功能码、字节计数和 CRC。一次帧分两次接收会先缓冲，直到完整才记 1 帧。
   自定义长度字段帧的总长度计算式为 `长度字段值 + 调整值`；例如 2 字节帧头 + 1 字节长度 + N 字节数据，应填长度偏移 `2`、长度字节数 `1`、调整值 `3`。
3. **坏数据**：日志结束时仍不够长的是“截断”；下一固定帧头提前出现的是“疑似截断并重同步”；CRC 不通过的是“CRC 错误并重同步”；帧头前单字节或多字节是“噪声”。它们不会混入丢包序号统计。
4. **连续序号**：仅在相邻有效 RX 帧的递增序号之间计缺号。跳变过大记为“疑似复位/异常”，不会夸大为丢包。
5. **循环序号**：序号变小只算候选边界。工具要看到至少两轮一致的完整范围，才会推导“单轮理论帧数”；每轮缺失编号可导出复核。
   若已知协议规定的序号范围，可手动填写起始序号与理论帧数，覆盖自动推断；该结论会被标为“手动设定”。
6. **收发核对**：一个 TX 只与其后第一个未配对 RX 匹配；超过设定超时的 TX 记“未响应”，没有待配 TX 的 RX 记“孤立”。若 RX 的地址/功能码在 TX 中出现，额外标为命令内容证实。此项不改变 RX 序号丢包率。
7. **时间定位与对比**：时间页只使用有效 RX 帧的记录时间；序号缺失计入后一个有效帧所在时间窗。多文件页不混合不同日志的字节流，也不自动为每个文件猜一套不同参数，而是复用当前已确认参数，保证横向结果可比。

> 这是一款协议层统计工具：它能证明“日志中没有出现的有效帧”，不能单凭日志区分无线链路丢失、串口驱动遗漏、SSCOM 保存遗漏或设备根本未发送。需要区分原因时，应同时保留 TX/RX、时间戳和设备端计数器。

## 运行源码

```powershell
py -m pip install -r requirements.txt
py .\src\serial_loss_gui.py
```

## 打包 Windows EXE

```powershell
py -m pip install -r requirements.txt pyinstaller
py -m PyInstaller --noconfirm --onefile --windowed --name SerialLossAnalyzer --icon .\assets\serial_loss_analyzer.ico --paths .\src --collect-all tkinterdnd2 .\src\serial_loss_gui.py
```

生成文件为 `dist\SerialLossAnalyzer.exe`。

## 限制

自定义协议的自动识别仍依赖重复帧头和递增字段；无序号协议无法计算“序号丢包率”。Modbus 自动识别要求至少 3 个 CRC 正确帧并能解释 80% 以上的接收记录，因此宁可提示手工配置，也不会把随机 HEX 误判为 Modbus。
